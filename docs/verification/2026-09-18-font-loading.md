# 首屏字体加载优化验收

## 范围与方法

基线为 `0571bd3` 的静态构建，优化版为同一提交上的字体子集改动。实现与维护边界见 [架构说明](../architecture.md#样式与主题)。两版均通过本地 Wrangler 提供 `.output/public`，未发布线上版本。

使用 Chromium CDP 禁用缓存，通过 Resource Timing 读取首次进入首页的字体响应体积。计时对照使用 1440 × 1000 视口、10 Mbps 下载速率、100 ms 延迟，不限制 CPU；这是本地受控网络测量，不代表真实访客速度。未运行 Lighthouse 或完整性能 trace，也未评估 INP、真实用户 Core Web Vitals。

## 下载量

| 首页实际请求的字体        | 优化前（字节） | 优化后（字节） |
| ------------------------- | -------------: | -------------: |
| LXGW WenKai 400           |      8,016,748 |         16,096 |
| LXGW WenKai 500           |      8,952,188 |         16,032 |
| Bricolage Grotesque Latin |         76,868 |         76,868 |
| 合计                      |     17,045,804 |        108,996 |

字体响应体积减少约 99.36%。正常首页没有请求完整中文字库。500 字重用于标题，400 字重由“跳到正文”链接触发，即使该链接尚未获得焦点也会下载。

同一限速条件下，从导航开始到最后一份字体响应结束，由约 14.04 秒降为 0.45 秒。首次内容绘制分别为 260 ms、272 ms，两版均先显示回退字体；本次改善主要是自定义字体下载与替换等待，不能解读成页面首次显示快了 14 秒。

## 外观与回退

- 1440 × 1000 与 390 × 844 的首页截图前后像素一致；标题边界和位置一致。
- 400、500 两个子集各包含 71 个字符；逐字对照源字体，轮廓与水平字宽一致。
- 浏览器实际使用的字体仍为 LXGW WenKai 和 Bricolage Grotesque，字重不变。
- Tab 聚焦“跳到正文”、404 标题与“回到首页”链接均使用正确字重的子集，手机宽度无横向溢出。
- 临时在浏览器标题中加入未收录的“春”，确认按需加载原 500 字重文件，继续使用 LXGW WenKai；检查后已刷新恢复。
- 子集保留版权及许可元数据；输出的第三方许可与主题包原文一致。
- `public/resume.pdf` 与构建产物的 SHA-256 均为 `e77a78a03624a402812a71c53c2efd4a43e9fc3c8d54b58d728dd6dd641bdbb6`。

## 工程检查

`pnpm check` 与 `pnpm build` 通过。静态构建使用 Node 24，字体处理在构建阶段完成，不增加浏览器运行时逻辑。构建仍有此前存在的 Nuxt / h3 未使用导入警告；字体资源没有未解析路径警告。

测量、字形对照与截图工具临时使用，没有新增验收脚本或 CI 检查。完整中文字库仍随产物提供，供未收录字符回退；新文案的常规构建会重新生成子集。
