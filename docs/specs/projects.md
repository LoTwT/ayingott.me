# 个人作品页实施规格

状态：首版于 2026-11-16 实现并完成独立评审，同日追加第二个作品及通用卡片的纸胶带材质与分层交互。本文维护当前要求；首版设计取舍、验收摘要和维护入口见[作品页交接](../decisions/projects-page.md)。

## 目标与范围

给现有 Nuxt 站点增加 `/projects`，让访客理解和访问 Lo 的个人作品。保持单页、单列，桌面左图右文，窄屏上图下文。沿用站点的字体、纸面、手绘细节与明暗主题。

当前展示用户确认的 [Nicole](https://github.com/LoTwT/nicole) 与 [Ayingott Design System](https://github.com/LoTwT/design-system)，依次排列，均使用 GitHub 作为入口。排版演示项目不进入正式作品清单。无需搜索、分类、排序控件、GitHub 热度数据、站内作品详情页或 `/works` 兼容跳转。

## 已确定的设计

### 布局与文字

- 全站沿用首页与文章页的共享 48rem 最大外框，左右内边距为 1.5rem，640px 起为 2.5rem；默认字号下桌面外框约 768px、实际正文约 688px。作品、导航与页脚和其他页面使用相同对齐线，不增加作品专属宽度变体，不扩大其他页面来匹配作品。
- 作品保持单列。列表可用宽度至少 38em 时采用约 4:5 的左右图文比例、2rem 间距，桌面预览约 292px；更窄时上图下文、间距 1.5rem，预览最大宽度 26rem。断点按实际容器和字号判断，放大字体后可自然改为上下排列。条目间距 4rem，标题组到列表 3rem，预览比例 8:5。
- 页标题沿用文章列表的字号层级：1.875rem、640px 起 2.25rem；作品名为 1.5rem、左右布局时 1.75rem；用途介绍为 1rem、左右布局时 1.0625rem；辅助信息 0.875rem。沿用主题字体与语义色，保持全站导航、主题、背景和页脚的既有行为。
- Nicole 使用用户确认的静态手写仙灵卡面：清晰大写 `N` 的字迹位于左下，末笔接入右上金色仙灵的尾尖，形成写完后向右上飞起的构图。画稿背景透明，底色使用作品列表共享的纸卡底色，与下方 Ayingott Design System 卡片一致。浅色主题使用比浅米金更深的柔和蜂蜜金字迹，深色主题保留浅米金字迹，仙灵保持橙金色；按站点主题切换，支持手动选择与跟随系统。卡外继续展示名称、用途、平台、功能与入口。沿用通用纸框、胶带、倾斜和指针动效，不在图片中重复绘制外框。
- 信息顺序：类别与序号、名称、一句话用途、平台或特点、入口。正文保持水平，作品预览轻微倾斜。说明文字用短句与自然换行，避免 `text-wrap: balance` 将“轻量”等词语强行拆开；不为固定桌面行数写入 `<br>`。
- 作品页标题“作品”；短介绍为用户确认的“一些做过的东西，一些正在做的东西。”，页面、SEO 与分享图共用单一来源。没有作品时显示“还没有作品”；仅一个作品时保持同一套尺度，不补空卡片。
- 列表后的 GitHub 个人主页入口使用“更多项目，在 GitHub”，保持低权重的收尾提示。

### 内容与入口

- Nicole 的介绍和特点依据公开 README，来源见[实施记录](#实施记录)：个人文章与文档用的轻量桌面 Markdown 编辑器；macOS、Windows、Linux；实时预览、沉浸、源码编辑模式。区分源码能力与已发布安装包能力，不编造下载量、版本、性能、经历或评价。
- Ayingott Design System 的介绍和特点依据其公开 README，来源见[实施记录](#实施记录)：面向 Tailwind CSS v4 的 `@ayingott/theme` 主题包，提供设计令牌、语义变量、基础样式、自托管字体与可访问性工具；不描述为 Vue 组件库。
- 每个项目分别维护用途介绍、可选特点（例如平台、文件形式、能力）与可用入口，不强制所有项目展示技术栈或相同字段。缺少字段时省略，同一地址不重复设置两个入口。
- 桌面应用与工具可以链接 GitHub，网页可以直接链接网站；按项目配置入口标签与地址。作品的源码入口使用“查看源码”，文档入口使用“查看文档”；Ayingott Design System 同时提供源码和[文档站](https://design.ayingott.me/)入口。
- Nicole 另提供“下载安装”入口，指向 [GitHub Releases](https://github.com/LoTwT/nicole/releases)，由访客选择版本与平台，不固定具体安装包地址。
- 使用轻量、清晰的静态类型数据维护手动顺序，不新增内容管理系统或运行时 GitHub 请求。

### 每个项目可定制的预览区

- 统一 8:5 比例、纸框、胶带、倾斜和留白；内部内容由项目独立决定，支持静态图片与项目专属 Vue 预览组件，类型与组件职责见[架构说明](../architecture.md#作品内容与构建)。新增作品不应要求修改整个列表的结构。
- 两张作品卡片共用列表内的 `--project-card-background`：浅色为 `#FEFBF5`，与站点 `#FCF6EA` 同一暖色调、略亮一档；深色沿用主题 `--surface-panel`，当前为 `#222220`。底色调整只作用于作品卡片，不覆盖其他页面的主题令牌。
- 通用外层将固定胶带与纸卡分层。胶带沿用黄、紫两色，以暖纸白柔化色彩，底色完全不透明，遮住下方的卡片边框与背景；明暗主题共用纸质底色，避免深色下过度暗沉。保留不规则短边撕口、轻微纤维纹理与接触阴影；纹理来自本地 [paper-tape-grain.svg](../../public/textures/paper-tape-grain.svg)，不使用运行时随机值。纸卡围绕胶带贴合点变换，专属预览内容仍由原有 `preview` 数据提供。
- 纸卡静止时保留清晰的硬边投影；随着抬起，近处投影逐渐柔化并降低不透明度，底部柔影同步扩散。整项悬停的弱提示保持可辨认，卡片悬停时进一步柔化，减轻厚卡板感；沿用同一抬起状态与过渡曲线，不改变三档之间的连续关系。
- Nicole 通过 [NicolePreview.vue](../../app/components/projects/NicolePreview.vue) 按站点 `.dark` 切换本地[浅色画稿](../../public/projects/nicole-cover-light.webp)与[深色画稿](../../public/projects/nicole-cover-dark.webp)。两张透明静态图绝对定位在同一内容区，以 `object-fit: contain` 完整展示，避免图片最小尺寸撑高并遮住底边框；不设置专属底色，可访问说明统一由 `preview.label` 提供。确认参考图、最终两张透明源画稿与完整编辑提示词保存在 [制作记录](../../assets/source/nicole-cover/prompt.txt)，不随站点发布；已弃用的纸底、墨棕字迹及中间平面稿已清理。原始品牌图标与早期动画仍见 [Nicole 留档](../../assets/archive/nicole/README.md)，当前卡面不播放归档动图。以后可独立替换为有来源的真实截图并保留出处；不能用代码绘制的假界面冒充截图。
- Ayingott Design System 使用已确认的字体与配色样张。由 [DesignSystemPreview.vue](../../app/components/projects/DesignSystemPreview.vue) 排版，左侧用 Bricolage Grotesque 展示 `Aa` 和字形参考线，下方以 Space Mono 显示 `AYINGOTT`，右侧排列天蓝、薄荷绿和暖黄色样。天蓝主色样与紫色胶带区分，明暗模式分别使用 `--color-sky-400` 和 `--color-sky-300`，字形与短字标随主题切换颜色。样张保持静态，沿用共享纸底、胶带和指针动效。
- 不要求安装或启动 Nicole，不访问用户正在编辑的私人文档，不上传私人数据。无需让整个应用运行在作品页中。
- 图片随响应式布局缩放，保持用途可辨认；没有图片也应有合理的字标或定制封面，不显示坏图占位。装饰元素对读屏软件隐藏，真实信息图片有恰当替代文本。

### 动效与可访问性

- Nicole 使用静态单帧图片，文字与仙灵不自行运动、不因悬浮换图。Nicole 与其他作品使用相同的纸卡指针跟随，具体行为如下。
- 直接复用站点现有的背景、蜡笔上色、蛋蛋、主题偏好、墨渍扩散和页面过渡组件，不另建简化的页面动效脚本。
- 标题与作品条目采用站点已有的纸片落下和手绘笔划语言，轻微错开入场，不给后续条目叠加过长延时。具体节奏由实施者在真实页面调试。
- 默认纸卡交互分静止、整项悬停、卡片悬停三档。悬停整项（包括文字区域）时，作品序号出现淡色手绘标记，标题轻移 2px，卡片以约 35% 的幅度轻微翘起，阴影向右下展开。进入卡片后，指针位置控制围绕胶带贴合点的姿态：靠近胶带时保持轻提示，向自由边缘移动时逐渐翘起，左右位置带出不同方向的轻微侧倾，并叠加不超过约 1.7° 的平面摆动，让正常桌面尺寸下的自由边缘产生可辨认的移动；俯仰约 0.84°～2.84°、侧倾不超过 3°，投影随离支点的距离展开，胶带保持固定。平面摆动从文字悬停的姿态接续，以指针相对支点的横向距离与向下位置决定方向和幅度；胶带换边后自然形成镜像响应。以固定占位测量指针坐标，校正静态倾斜后按动画帧合并更新局部 CSS 变量，不由变换后的纸卡反推坐标；不同条目互不保留上一张卡片的指针姿态。
- 弱提示使用 180ms、进入卡片使用 220ms 的平顺曲线，从当前画面继续过渡；进入后跟随改用 140ms，让移动响应更利落，进出时保留缓冲。直接进入卡片时即按当前位置同时开始翘起与投影，无需先完成弱档。卡片与文字之间切换不回弹，仅离开整项时使用约 380ms 的既有贴纸曲线轻微回弹一次。指针离开或取消、系统切换为减少动态效果或粗指针、组件卸载时清理跟随状态、待执行帧与跟随切换计时器。纸卡与胶带共用一个稳定占位，变换不改变列表排版与点击区域。
- 条目内链接键盘聚焦时复用条目的轻提示，链接继续使用手绘下划线与原焦点环。触屏不启用悬浮动效；减少动态效果时只即时显示序号提示和卡片阴影，不移动标题或纸卡，不为整项和内部链接叠加重复操作。
- 2026-11-16 用户追加细调：作品入口与收尾 GitHub 链接的手绘线更靠近文字，留出字母下伸部的空间；保留文字颜色层级，不缩小44px点击热区，减少动态效果时直接完成同样反馈。[内容入口配色](design.md#内容入口配色)与[内容入口线形](design.md#内容入口线形)规定按稳定项目标识、个人主页入口键分配三色和上拱尾段；绘制与擦回全过程保持入口本色，交互状态仅控制显隐，顶部导航保留原样。
- 同日用户确认收尾GitHub默认不需要半条线；与作品入口一致，仅在hover / focus-visible时画出，指针离开或失焦时同色擦回，文案仍为“更多项目，在 GitHub”。
- 遵循 `prefers-reduced-motion`，保留键盘焦点、语义标题和现有跳到正文入口。支持明暗和跟随系统；不得回退已修复的主题闪烁、移动端横向溢出等问题。

## 验收标准

1. 直接访问和站内跳转均可打开 `/projects`；按顺序展示 Nicole 与 Ayingott Design System，内容、GitHub 入口和可定制预览正确，不包含设计稿样例、审阅控制或虚假指标。
2. 页面与共享导航、主题、背景和页脚正确组合；单作品与多作品均能正常呈现，样例验证数据不进入生产清单。
3. 桌面单列左右、窄屏上下符合共享宽度下的尺度；检查大屏、中等视口、手机、布局断点及放大字号，无覆盖、裁切或横向溢出；文案换行自然。相同视口与根字号下，实测首页、文章列表、文章正文、标签、作品、404 的共享外框、左右内边距及对齐线一致，文章独立阅读 measure 不作全栏宽要求；页间切换时导航与页脚不因页面宽度横向跳动。检查浅色、深色、跟随系统、键盘焦点及减少动态效果。
4. `pnpm check` 和 `pnpm build` 通过；验证生成 HTML 的实际内容与 SEO、sitemap、页面资源及预渲染结果，不只看开发服务器。
5. 在实际 Nuxt 页面中验证入场、悬停、导航、主题扩散、背景和蛋蛋；对首页、文章/标签与错误页做与变更相称的回归检查。
6. 按受影响的行为和风险选择验证，优先使用[开发约定](../development.md#检查)中的现有命令或必要的临时检查，不为静态视觉细节搭建冗余测试框架。独立评审区分必修问题与后续建议。
7. 报告代码目录、任务分支、实际验证结果、截图/预览、已作实现取舍、未验证项和临时文件路径；失败如实报告。
