# 0004：加入文章发布

日期：2026-10-10。状态：已采用。功能规格见 [文章发布](../specs/articles.md)。

## 背景

2026-10-09 曾确定不加入作品、文章或博客页面，也不接入内容系统，相关决定见 [0001](0001-project-foundation.md)。次日，用户确定加入文章，并要求从零设计与选型，不沿用旧站博客的实现。原有文档中与文章相关的限制已一并移除。

## 选型

| 候选                                                 | 结论 | 理由                                                                                          |
| ---------------------------------------------------- | ---- | --------------------------------------------------------------------------------------------- |
| Nuxt Content v3                                      | 采用 | 官方方案，与现有 Nuxt 4 SSG 同栈；提供集合查询、Shiki 高亮、remark/rehype 插件与 MDC 组件语法 |
| 自建 Markdown→Vue 编译（如 `unplugin-vue-markdown`） | 否   | 列表、标签、RSS 所需的索引都要自行实现，最终会是一个简化版的 Nuxt Content                     |
| 独立博客引擎（VitePress、Astro）                     | 否   | 会引入第二个框架与构建流程，无法复用现有的站点框架、主题与字体子集管线                        |

图片采用 nuxt-content-assets，代价是多一个第三方依赖：

- 换来的好处：在其他编辑器中写好的文章，整个目录搬进来即可使用，相对路径与原编辑器预览都不受影响；构建时还会补全图片尺寸。
- 依赖风险：它依赖 Content 的内部机制，Content 升级时可能需要等它适配。退出路径见规格。

旧博客实现提供了两条经验：

- 日期按字符串处理，避免时区偏移。
- 内容扫描不手写 YAML 解析。

## 评审修订

方案由 Claude 起草，Codex 评审三轮。评审意见均对照 `@nuxt/content` 3.16.1、`nuxt-content-assets` 3.0.1、`remark-mdc` 3.11.1 与 `@nuxt/cli` 4.0.0 的发布源码核实。

- Content 的集合 schema 不会阻止错误内容发布，解析失败也只会警告并跳过该文件。因此改为独立的构建期校验，并显式列出预渲染路由。
- `remark-mdc` 的 `parseFrontMatter` 不检查 YAML 错误，校验改用 `yaml` 的 `parseDocument` 并检查错误。集合收录范围收窄到与校验范围一致。
- 图片尺寸需要显式开启，并且模块顺序有要求。
- XML 路由不会被爬取发现，需要显式加入预渲染。
- `NITRO_PRESET` 中含 `cloudflare` 时，Content 会切换到 D1，因此加入构建断言。
- 字体不能按字重分别收字，否则会漏字。退路需要同时覆盖正文、标题与代码字体。
- Lighthouse 的 SEO 标准需要限定检查环境；CLS 按原始值判断。

## 用户决定

- **不设草稿机制**：合入 `main` 即发布，未完成的文章不进入 `main`。原方案中的草稿目录、草稿开关与草稿隔离验收全部取消。
- **只用标签，不设分类**：个人博客的文章量不大，同时维护两个维度会产生重叠。
- **字体按内容生成子集**：实测通用分片的下载量是按内容生成子集的 5–8 倍，见规格中的对比。此外，`cn-font-split` 依赖安装阶段下载的原生库，会给 Cloudflare 构建增加外部依赖。
- **文章入口放入 Header 导航**：首页的 GitHub、邮箱、简历图标属于个人信息，与站内页面不是一类，因此不在首页增加第四个图标，改为全站 Header 增加“首页”“文章”导航；这也解决了内页没有回到首页入口的问题。
- **Header 不吸顶，文章末尾加入“全部文章”入口**：实现后预览时讨论过 Header 吸顶。吸顶的 Header 会长期占用手机屏幕，需要不透明底色而与主题切换的光幕冲突，还要处理锚点偏移，因此保持随页面滚出。读完长文时 Header 已不可见，改为在文章末尾放置贴近页脚的“全部文章”入口，具体约定见 [设计方向](../specs/design.md#全部文章)。
- **每篇文章生成分享卡片**：原定不做单篇分享图、统一沿用站点卡片。实现后用户决定为文章单独设计分享卡片，卡片至少包含标题与日期，因此只能为每篇文章各生成一张；文章可通过可选的 `image` 字段把图片合成到卡片右侧。为此新增构建期依赖 `satori`、`@resvg/resvg-js` 与 `image-size`，三者都没有安装脚本。约定见 [文章发布](../specs/articles.md#seo-与分享) 与 [设计方向](../specs/design.md#文章分享卡片)。
- **视觉保持克制**：文章相关页面不使用 `brutal` 风格的粗边框与硬阴影，只沿用主题的配色与字体，具体约定见 [设计方向](../specs/design.md)。
- **一次性交付**：方案与实现放在同一个 PR 中，不分阶段。
