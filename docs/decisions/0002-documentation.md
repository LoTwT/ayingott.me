## Agent 配置与项目知识

`AGENTS.md` 使用 `agent-config-setup` 的通用规则模板，`CLAUDE.md` 通过 `@AGENTS.md` 引用它。项目知识集中在 `docs/`，以 [文档索引](../index.md) 按任务导航，避免在 Agent 文件、README 和专题文档中重复维护版本与阶段说明。

## 按职责与维护方式分目录

2026-09-14 先将项目文档整理为扁平结构。2026-09-15，用户指出现有内容需要目录划分，因此按内容职责和后续增长方式调整：

| 目录            | 内容                             | 维护方式                                   |
| --------------- | -------------------------------- | ------------------------------------------ |
| `product/`      | 产品目标、范围、页面与交互设计   | 随当前产品方向更新                         |
| `engineering/`  | 开发约定、技术实现、部署操作     | 随当前代码和配置更新                       |
| `decisions/`    | 决策及其原因、适用范围和调整背景 | 使用稳定编号记录主题，变更时保留日期与原因 |
| `verification/` | 已执行的检查、部署和验证结果     | 按日期与验收对象新增文件，保留当时结论     |

产品和工程文档需要反映当前约定；决策与验收记录会持续积累。分目录后，当前规则与历史证据各有明确位置，文档增长时仍能按任务查找。

现有产品要求中的布局约束单独归入设计文档；开发与部署保留在同一工程目录。暂不继续拆分只有少量内容的技术章节，也不预建没有内容的目录。

## 导航与命名

`docs/index.md` 保持统一入口，直接链接各主题与记录，当前不为每个子目录重复建立索引。新增文档时更新入口。

决策文件使用 `0001-topic.md` 形式，保留稳定编号；验收记录使用 `YYYY-MM-DD-topic.md` 形式。同一天不同对象单独记录，不把新检查结果写回旧记录中的统计。
